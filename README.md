# Week07 TODOリスト

POSSE PH1 Week07「DOM操作・イベント」のPOSSE課題です。

## 使い方

1. `index.html` をブラウザで開く
2. 入力欄にタスクを入力して「追加」を押す
3. 「完了」で打ち消し線を切り替える
4. 「削除」でタスクをリストから取り除く

## 実装メモ（PR本文）

### 1. 「追加」ボタンを押したときの処理の流れ

フォームの `submit` イベントを受け取り、`preventDefault()` でページ遷移を止めます。次に `input.value` から入力値を取得し、`trim()` で前後の空白を取り除きます。空文字なら何も追加せず、入力欄にフォーカスを戻します。値がある場合は `createElement` で `li`、タスク文字列、ボタンを作り、`appendChild` でDOMに追加します。最後に入力欄を空にして、件数表示を更新します。

### 2. `querySelector` のID指定とクラス指定の使い分け

フォーム、入力欄、リスト、空状態メッセージなど、ページ内に1つしかなく役割が固定されている要素は `#todo-form` のようにID指定で取得しました。作成するタスクの文字列や操作ボタンは複数存在するため、作成時に `className` でクラスを付けています。今回、既存要素の取得ではID指定を中心に使い、複数の同じ役割を持つ要素にはクラスを使い分けました。

### 3. `classList` のメソッドと選んだ理由

完了状態の切り替えに `classList.toggle("is-completed")` を使いました。完了ボタンを押すたびに、打ち消し線のクラスを追加・削除できるためです。また `classList.contains("is-completed")` で現在の状態を確認し、ボタンの表示を「完了」と「戻す」に切り替えています。

### 4. 詰まった場所と解決方法

タスクを動的に作成するため、HTMLに最初からボタンを置くのではなく、`createTask` の中でボタンを作成してイベントを登録する必要がありました。`li` を追加した後ではなく、ボタンを作った直後に `addEventListener` を登録する形に整理して解決しました。作成した要素が画面に表示されるには `appendChild` が必要なことも確認しました。

### 5. 削除ボタンのUX設計

削除は確認なしで即時削除する方式を採用しました。1件のタスクを素早く整理するアプリなので、毎回ダイアログを表示すると操作が止まると判断したためです。「削除」ボタンを淡い赤色にし、完了ボタンと見た目を分けて誤操作に気づきやすくしています。重要なメモを保存する用途ではなく、必要なら再入力できる前提でこの方式を選びました。

### 6. 確認結果

- スマホ幅 375px：入力欄とボタンが収まり、タスクの操作ボタンは縦並びで確認
- PC幅 1280px：カードが中央に配置され、入力欄とボタンが横並びで確認
- タスク追加、空入力、完了状態の切り替え、削除、件数表示を確認
- ブラウザのConsoleにエラーがないことを確認

### 7. AIとの比較

AIに同じ要件で実装させた場合も、`createElement`、`appendChild`、`classList.toggle` を使う基本構成は同じになると考えました。

- 正しく実装できていたこと：入力値の取得、空入力の除外、タスク追加、完了状態の切り替え
- 足りなくなりやすいこと：`trim()` による空白だけの入力の除外、`preventDefault()`、スマホ幅でのボタン配置、削除UXの理由
- 自分が判断・修正した箇所：削除を即時削除にする判断、完了後に「戻す」へ表示を変えること、レスポンシブな操作ボタン配置
